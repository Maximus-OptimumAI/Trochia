<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| error contexts → Sentry | error payloads may carry user data / financial figures that must not leave the system |
| client → Amplitude | browser events are spoofable; revenue/lifecycle events must come from the server |
| ai/ → Langfuse | trace payloads include prompts/responses — must not include customer data beyond what's necessary (in Phase 1, only the trivial health-check prompt) |
| Resend → recipient | transactional mail leaves Trochia; only system mail to the founder — never autonomous investor email |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-1-25 | Information Disclosure | financial figures / deck text / transcript bodies / PII reach Sentry via an error context | mitigate | `beforeSend` deep-scrubs the shared `SENSITIVE_FIELDS` set (single source in `logger.ts`); `beforeBreadcrumb` drops console breadcrumbs; the anti-pattern "log IDs and event types only" is enforced by the redacting logger + the no-console lint |
| T-1-26 | Spoofing / Tampering | a client forges a `checkout_completed` Amplitude event to fake a conversion / inflate revenue metrics | mitigate | revenue/lifecycle events (`checkout_completed`, `tier_selected` finalization) fire server-side from the Stripe webhook (Plan 07) via the Amplitude node SDK — the browser SDK only fires UI-state events |
| T-1-27 | Information Disclosure | Langfuse traces leak customer data (prompts/responses) | mitigate (pattern now) | in Phase 1 the only AI traffic is the deploy-time Haiku ping ("Reply with {\"ok\":true}") — no customer data; from Phase 2+, the untrusted-input delimit + the "log token counts not bodies" discipline keep traces clean; Langfuse Cloud's retention is documented in the vendor data-flow inventory (Plan 06) |
| T-1-28 | Spoofing / Repudiation | a forged transactional email impersonates Trochia | mitigate | the sending domain is verified (SPF/DKIM/DMARC via Resend's domain verification); the from-address domain follows `SITE_URL`'s host, never hardcoded (so the trochia.ai migration is an env swap) |
| T-1-29 | Tampering | an autonomous founder-email-send sneaks in via the Resend client | mitigate | `lib/email/client.ts` is documented + scoped to system mail only; founder emails (investor/intro/follow-up) go via the founder's own Gmail through the founder-approval Dialog (XC-02); Code Reviewer rejects Resend usage for founder-authored external mail |
| T-1-30 | Information Disclosure | secrets (Sentry auth token, Amplitude/Langfuse/Resend keys) committed or exposed in `NEXT_PUBLIC_*` | mitigate | only `NEXT_PUBLIC_SENTRY_DSN` and `NEXT_PUBLIC_AMPLITUDE_API_KEY` are client-public (DSN/public API keys are designed to be public); all secret keys are server-only in `env.ts`; `.gitignore` keeps `.env*` |
</threat_model>
