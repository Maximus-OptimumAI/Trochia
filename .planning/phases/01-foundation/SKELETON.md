# Walking Skeleton — Trochia AI

**Phase:** 1 (Foundation)
**Generated:** 2026-05-12

## Capability Proven End-to-End

> A founder signs in with Google, picks a tier, completes Stripe Checkout (7-day trial, card on file), and lands on `/app` seeing their tier — exercising Supabase Auth + Postgres RLS + Stripe + the idempotent webhook + tRPC + `entitlements()`, deployed on Vercel at `trochia.asranest.com`.

The thinnest real end-to-end slice (D-08, founder's words): `signup → tier picker → Stripe Checkout → webhook updates accounts.subscription_status → user lands on /app showing their tier`. "If this slice works, the foundation works."

Built and deployed by **Plan 07** (`01-07-PLAN.md`); proven by `e2e/skeleton.spec.ts` + the manual post-deploy checks recorded in `01-VALIDATION.md`.

> **Why the skeleton lands at wave 5, not wave 1:** intentional, per D-08. The Walking Skeleton (signup → tier picker → Stripe Checkout → webhook → /app shows the tier) genuinely needs the scaffold + lint/CI (Plan 01), the design system + `providers.tsx` (Plan 02), the Supabase schema + RLS + tRPC context (Plan 03), the `ai/client.ts` chokepoint + Inngest (Plan 04), the observability wiring (Plan 05), and the compliance plumbing — DPA + data-rights (Plan 06) — in place first. Building it earlier would mean stubbing all of those and re-doing the wiring. The late skeleton is by design, not by accident; every later phase builds vertical slices on top of it without renegotiating these decisions.

## Architectural Decisions

| Decision | Choice | Rationale |
|---|---|---|
| Framework | Next.js 16.x App Router (pinned exactly; Turbopack default; React 19 + React Compiler 1.0; `proxy.ts` not `middleware.ts`; async `params`/`searchParams`) | Greenfield ⇒ start on the current major (D-01); no migration cost |
| Hosting | Vercel Pro (Fluid Compute; preview deployments; 800s `maxDuration`); `trochia.asranest.com` now → `trochia.ai` via an env-var swap (`NEXT_PUBLIC_SITE_URL`/`NEXT_PUBLIC_APP_URL` — never hardcoded) | D-01b; FND-08; the migration must be zero code changes |
| Data layer | Supabase Pro — Postgres + pgvector (HNSW, enabled now, populated Phase 2) + Storage + Realtime; Drizzle 0.44 manages schema + migrations; Supabase **publishable/secret** keys (never anon/service_role) | D-01b, D-03, FND-02; pgvector handles 10M+ vectors, Postgres handles 100K+ users — no separate vector DB |
| Tenant isolation | Postgres **RLS default-deny** on every tenant-scoped table (the backstop — physically can't leak) + tRPC `protectedProcedure` injecting `ctx.tenantId`/`ctx.region`/`ctx.db` (the ergonomic layer) + an `/app` server-side subscription gate (`proxy.ts`); a narrow audited service-role client for webhooks / Inngest jobs / account deletion only. RLS schema-scan CI test + two-user isolation Vitest test enforce it. RLS-JWT-claims plumbing: a custom `tenant_id` JWT claim via a Supabase Auth Hook (one-business-per-account in Phase 1 per D-03) — see `01-03-SUMMARY.md` for the resolved wiring. | D-04, FND-03; defense in depth — never app-code-only (PITFALLS §3) |
| Auth | Supabase Auth — Google SSO only at MVP; `@supabase/ssr` PKCE cookies in `proxy.ts` + server components; 1h JWT expiry + 30d inactivity timeout (+ best-effort 90d absolute cap, per platform support — see `01-07-SUMMARY.md`); magic-link + TOTP MFA deferred to Phase 8 | D-10, FND-04; free, RLS-native, one fewer vendor |
| Billing / entitlements | Stripe — Pre-Raise $49/$39-annual + Active Raise $199/$159-annual (Close Mode $399 + Alumni $19 present as data but inactive — Phase 11); Customer Portal for self-serve; 7-day trial + card-on-file at signup (`trial_period_days: 7` + `payment_method_collection: 'always'`); no permanent free tier. The **idempotent webhook** (dedupe on `event.id`) is the source of truth — writes `accounts.subscription_status`/`tier`/`current_period_end`; an Inngest reconciliation cron re-pulls from Stripe as the safety net. `entitlements(account)` is a **pure function over the persisted status** — never calls Stripe inline; the tier→features map is data so adding a tier is a data change, not a refactor. `/app` is hard-gated from day 1 (no active trial-or-sub → `/reactivate`). | D-02/D-02b/D-02c, FND-05, FND-06; PITFALLS §18 (webhook reliability) |
| Background jobs | Inngest v4 — a single `serve()` endpoint at `/api/inngest`, 4 retries default, per-key concurrency limits; a `jobs` table + Supabase Realtime for UI status polling; real functions (the deploy-time Haiku health-check, the Stripe reconciliation cron, the soft-delete purge cron) + stub functions for the future workloads (deck parsing, embedding, transcription, brief enrichment, e-sign webhooks, scheduled reminders). | D-07, FND-11; the slow-work lane — never `setInterval`/a bespoke queue |
| AI | A single `ai/client.ts` chokepoint — prompt caching on the stable prefix (`cache_control: {type:'ephemeral'}` breakpoints, instrumented in Langfuse — not assumed), model routing (Haiku 4.5 / Sonnet 4.6 / Opus 4.7 by task class), Zod-typed structured outputs via forced tool use (one repair retry), an OpenAI/Codex fallback behind a config flag (no DB credentials, never the default). `@anthropic-ai/sdk` is imported nowhere else (ESLint-enforced); `safe-engine`/`cap-table-engine` (future) may not import `ai/**` (ESLint-enforced). A deploy-time ~10-token Haiku health-check produces the first real Langfuse trace before Phase 2 builds on it. | D-09, FND-09, XC-06, XC-07; "mandatory in the docs ≠ automatically done" — wire + verify caching now |
| Observability | Sentry (errors — client/server/edge, source maps, PII scrub feeding off the redacting logger), Amplitude (product events — browser + node SDKs; the onboarding-funnel taxonomy), Langfuse (every production Anthropic call — cache hit rate / tokens / latency / cost), Resend (transactional email — typed react-email templates, Trochia→founder system mail only; founder investor-emails go via the founder's own Gmail through the founder-approval Dialog, never Resend). PostHog deferred. | D-13, FND-07, XC-02 |
| Compliance / privacy | A banned-string CI check (reads `tasks/banned-strings.txt`, with a "not legal advice" allowlist) + a redacting logger + a no-raw-`console.*` ESLint rule + `ai/` import-boundary lints — all live in Phase 1 (D-06a–d). A clickwrap DPA (GDPR/UK-GDPR/DPDP/LGPD-grade, versioned acceptance on `legal_acceptances`+`accounts`, downloadable PDF). Data-subject-rights plumbing: on-demand full data export → tenant-isolated Storage → signed URL → email; account deletion → `accounts.deleted_at` soft-delete → the Inngest purge cron after 30 days; restore-within-30-days. A vendor data-flow inventory (`docs/vendor-data-flow.md`) backing XC-01 ("no customer data in training" — Anthropic no-training/7-day retention; the OpenAI fallback + Claude-Code build tooling explicitly covered). | D-06/D-11, XC-01/XC-03/XC-04/XC-05 |
| Multi-region seam | `accounts.region` enum (`us` | `in`; `eu` reserved for V2) + a `getDbForRegion(region)` factory that branches per region but returns the US Supabase client on every branch today. US + UK share the US region (UK contractual at MVP). When the first India founder signs up: provision the India-region Supabase project and flip that one branch — no other code changes. Built without over-engineering full multi-region machinery. | D-05, FND-10 |
| Design system | shadcn/ui initialized + themed to the brand tokens (NOT a stock preset); Tailwind v4 CSS-first config matching `docs/DESIGN-REFERENCE.md` exactly (the 8 color tokens `paper`/`ink`/`graphite`/`stone`/`signal`/`success`/`warning`/`danger`; 7 custom `fontSize` keys spanning Geist's 4 + Inter's 3; Geist Mono on native `text-base`/`text-sm`); Geist/Inter/Geist Mono via `next/font`; light mode only at Phase 1. Cross-cutting primitives: the founder-approval Dialog (XC-02 — noun-bearing `Send {thing}`), the destructive-confirm Dialog ("Keep {noun}" dismiss, optional typed-confirmation), the legal-disclaimer banner, empty/error/skeleton states, the section divider, the app shell, the marketing top bar, the footer. `/styleguide` (session-gated) renders all 19 sections — a Phase 1 exit gate. Lighthouse > 90 on `/` — a Phase 1 exit gate. No Tailwind color/font outside the token system (Code Reviewer rejects). Aesthetic target: harmonic.ai + firecrawl.dev (operator-grade, near-monochromatic, single Signal accent). | D-14, the UI-SPEC (approved 2026-05-12), `docs/BRAND.md`, `docs/DESIGN-REFERENCE.md` |
| Directory layout | A **single Next.js package** (NOT a monorepo) with App Router route groups: `src/app/(marketing)/` (homepage, `/pricing`, `/manifesto`, `/legal/*`), `src/app/(app)/` (`/app`, `/onboarding`, `/styleguide`, settings, billing, module placeholders), `src/app/(auth)/` (`/sign-up`, `/sign-in`), `src/app/api/{trpc,webhooks/stripe,inngest}/`; plus `src/server/` (tRPC), `src/db/` (schema, RLS, region factory, migrations), `src/ai/` (the chokepoint), `src/modules/` (billing, data-rights, compliance), `src/inngest/`, `src/lib/` (env, logger, crypto-stub, errors, analytics, langfuse, supabase clients, email), `src/components/` (ui, primitives, shell, marketing, dashboard, onboarding, brand). `proxy.ts` at `src/proxy.ts` (Next 16's `PROXY_LOCATION_REGEXP` matches `(?:src/)?proxy` — the file lives at the project root or `src/`, NOT inside `src/app/`). `docs/vendor-data-flow.md`; `tasks/banned-strings.txt`; `tasks/lessons.md`; `.github/workflows/ci.yml`. | RESEARCH.md "Recommended Project Structure"; a monorepo adds tooling overhead for zero benefit when marketing + app share the brand system + components + deploy target |

## Subsequent Slice Plan

Each later phase adds one vertical slice on top of this skeleton **without altering its architectural decisions** (the framework, data layer, RLS pattern, auth, billing/entitlements model, the `ai/` chokepoint, Inngest as the slow-work lane, the brand token system, the deterministic-vs-LLM firewall, the compliance guardrails):

- **Phase 2 — Knowledge Layer + Memory:** the Business Memory + Pipeline Memory spine — paste/upload existing AI context → Claude-Sonnet extraction → a confirmation UI → the canonical relational record; the curated corpus + Business Memory embedded into pgvector via an Inngest pipeline; the grounded+cited ambient Q&A sidebar; memory-staleness prompts; the unified raise timeline (XC-08). *("is the moat real?" gate on design-partner data.)*
- **Phase 3 — Pitch Lab Deck Reviewer:** deck parsing (LlamaParse + a `pdf-parse` fallback) → the Claude-Opus reviewer with structured output over a defect taxonomy → the review dashboard with accept/reject/edit → a Langfuse-hosted eval harness in CI gating the false-positive rate + zero fabricated slide refs; deck-link tracking (PITCH-09).
- **Phase 4 — Investor Pipeline:** VC/accelerator match (ranked, scored, rationale'd) → the application tracker (pre-loaded bank, AI-drafted answers, calendar reminders) → the outreach drafter (Exa + Firecrawl enrichment, founder-approved, sent via the founder's own Gmail) → the warm-intro mapper → bulk actions + CSV import/export.
- **Phase 5 — Live Raise (MVP soft-launch checkpoint):** pre-call briefs → transcript ingestion + auto-summary → the post-call follow-up drafter (founder-approved Gmail) → the Pipeline Memory drag-and-drop kanban. **HARD go/no-go: 25 design partners onboarded & paying + activation thresholds met — else PRD v1 (MVP-only) fallback before any V2 work.**
- **Phase 6 — Voice Pitch Coach + Q&A Drill + Browser Extension** (V2): in-browser audio capture (MediaRecorder) → Deepgram Nova-3 transcription → deterministic voice metrics (Web Audio RMS + a custom filler detector — **no permanent third-party prosody API**) + Opus structure scoring → the scorecard; the Q&A Drill; the Chrome/Edge Knowledge-Pack-sync extension. *(Needs phase research at kickoff — the Hume sunset ~June 2026.)*
- **Phase 7 — Data Room Orchestration** (V2): the vertical-aware checklist → Google Drive `drive.file`-scoped folder orchestration (the consent screen verified to request exactly `drive.file`) → per-investor share links + access analytics → the DDQ filler; Gmail pipeline sync; pipeline custom fields; cross-module fact-conflict surfacing (XC-09).
- **Phase 8 — Legal Stack Recommender + EU Residency** (V2): the vendor decision-tree wizard (vendor selections only — never legal advice, lawyer disclaimer on every screen) → the compliance checklist → affiliate tracking; EU data residency live via the Phase-1 region seam; TOTP MFA. *(Non-skippable Compliance Auditor pass on the UPL/disclaimer surfaces.)*
- **Phase 9 — Raise Ops Core (SAFE + Cap Table)** (V3): the deterministic SAFE generator (vetted templates + variable substitution only, **no model-generated legal language**; an un-bypassable lawyer-review gate; `no-restricted-imports` from `ai/`; a Security Engineer audit) → the deterministic cap-table engine (unit-tested, matching a 30-scenario oracle 100%, never an LLM) → Excel/Carta hand-off. *(Critical path: the law-firm SAFE-template partner must be locked first; needs phase research at kickoff — the off-Vercel `.docx`→PDF converter.)*
- **Phase 10 — F&F Round Manager + E-Sign** (V3): the F&F CRM (a tracker, **never a "fund"**; not-an-adviser copy on every screen; a banned-string CI check + a Compliance Auditor pass verifying zero "rolling fund"/"fund"/"investment vehicle"/"adviser") → Dropbox Sign / DocuSign e-sign (ESIGN/eIDAS-compliant) → idempotent cap-table writeback within 30s via the webhook → Inngest path.
- **Phase 11 — Polish + Close Mode + Alumni + Public Launch** (V3): the Alumni Investor Update Generator → Close Mode + Alumni tier billing live (the `entitlements()` data change) → the Founder Audit add-on → `/changelog` with real entries → the launch surfaces (banned-string clean) → SOC 2 Type I prep begun. **Public launch gated on ≥3 founders having closed real rounds while using Trochia.**
